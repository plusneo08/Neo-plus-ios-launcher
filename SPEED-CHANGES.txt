PART 1 - speak while the reply is written
  CallConversation.kt  caller calls stream the reply; voice starts after the first sentence; opening + fixed phrases made at answer time;
                       waits: opening 1400->800 ms, before listening 450->200 ms, end-of-speech silence 1600->1100 ms
  WakeCallActivity.kt  wake-up / morning / "call Neo" calls speak while the reply is written
  Speaker.kt           live speech reports when it is finished; pauses between spoken pieces ~45% shorter
  LiveReply.kt         optional onSpoken callback
  CallAssist.kt        Llm.warm() when the phone rings

PART 2 - lighter prompt, "one moment" filler, faster voice give-up
  NEW      CallPrompt.kt   short call prompt (~1.5k characters instead of ~33k) + the rule for when the full one is needed
  CHANGED  Agent.kt        respond(..., useSearch) : null = as before, false = no live web search for this request
  CHANGED  WakeCallActivity.kt
      - plain conversation uses the short prompt and no live search; a request that may need the phone or live information
        (words such as open, call, send, set, play, weather, news, today, find, check ...) uses the full prompt as before
      - if the short prompt is not enough the model answers NEED_TOOLS (never spoken, not an action) and the same request is
        asked again with the full prompt
      - a heavy request that has not started to speak after 1.2 s plays "One moment." / "Let me check that." / "Sure, one second."
  CHANGED  CallConversation.kt   caller calls: same filler after 2.2 s without a voice
  CHANGED  Speaker.kt
      - Speaker.filler(): plays on its own track; the real reply waits for it to end (max 2 s) instead of cutting it; Speaker.stop() stops it
      - Gemini voice gets 2.5 s for its first words (was 9 s / 5 s), one retry of 3 s (was 10 s), then the phone's voice takes over
